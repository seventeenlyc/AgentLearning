# transformer理解

原始token通过查找向量表得到embedding x（n×768），通过加上位置参数p（&#x6E;*×*&#x3768）得到$Z$（n×768）;\
$Z$通过和$W_q^i$（768×64）进行变换成为$Q_i$（n×64），再根据$\frac {QK_i^T} {8}$计算$S_i$, (其中$K_i^T$(64×n)\
通过$softmax(S_i)$得到注意力权重weight（n×n），\
再和$V_i$（n×64）相乘得到$head_i$（n×64），最后拼起来变成H（n×768），再乘以$W_O$得到$H'$。 \
$H'$再和$Z$做残差连接得到$norm$,再交给FFN做理解。
图解
```text
Z
│
├───────────────┐
│               │

+ ←─────────────┘

```
以上是一层transformer，经历多层以后才进行输出。

# 模型参数理解

模型参数可以理解为可训练的参数（$W_Q$,$W_K$等)的矩阵面积总和（向量和标量理解为宽度为1的矩阵）

# 解答：第一版
1. RNN的上下文是固定的，无法得到n个token前的信息，而改进的LSTM虽然有了记忆，但是每一次分析都是串行计算，
需要等前面的token处理完了才能处理后面的，效率过低。而transformer保留了hidden state的同时，通过矩阵同时读入多个token实现了并行计算
2. Attention是注意力机制，能让模型把指代等关系串起来，让模型能建立起两个token的相关性（如“我在广州出生。我家乡在哪？”，把哪和广州、出生地和广州连了起来）
3. Q：需要处理什么token？K：这个token是怎么样的？V：如果选择了这个token，它对注意力的影响有多少？
4. 一个头一般只能处理一种关系，比如说时间、空间。多个头可以让模型在不同的角度进行处理，把语句间的指代、空间、时间等关系理清楚。
5. 如果没有位置编码，模型在处理信息的时候无法知道每一个词的空间关系，交换词语的顺序对分析关系没有影响，而交换顺序往往会有不同的语义，所以需要一个位置编码规定每一个token的位置
6. 相比于传统的Encoder-Decoder，GPT不需要一次性把所有的信息都读完再进行分析，可以通过逐token读取的方式来读信息，忽略未来的token，配对已经读入的信息，输出时再把输入和已经输出的进行串联。

# 第一版审查结果
审查结果：**整体理解已基本正确，可继续学后续内容。**

主要问题只有 4 个：

1. **RNN**：不是“完全拿不到很早的信息”，而是**长期依赖难保留，且串行计算效率低**。
2. **QKV**：V 不是“影响有多少”，而是**真正被取回的信息内容**；影响大小由 QK 算出的权重决定。
3. **多头注意力**：不要说“一个头只能处理一种关系”，应说**不同头在不同表示空间中关注不同关系**。
4. **Decoder-Only**：GPT 不是像 RNN 那样逐 token 串行读取 Prompt；它可以并行处理已有 Prompt，只是通过 **Causal Mask** 限制不能看未来 token。

其余内容基本正确，尤其是 Attention 和位置编码的理解已经够用了。
# 解答：第二版

1. RNN的早期信息，经过多轮传递以后，很难保留。而改进后的LSTM改善了长期保留信息的能力，但是都还有串行计算的缺点，必须处理完前一个信息才能处理后面的信息，效率太慢。\
而transformer既保留了信息的传递高效，又是并行处理信息，效率高。
2. Attention是注意力机制，让模型串联起多个token之间的相关性。
3. Q：我想找什么信息？K：这个token能提供什么信息？与Q匹配能得到什么？V：这个token真正提供的内容是什么？
4. 单头不能让模型建立起很好的多角度分析能力，多头可以让模型在训练后的各种角度理解token之间的关系。
5. 位置编码是对信息输入顺序的确认，区分同样的两个词因为顺序不同而产生完全不同的信息。
6. 传统transformer是Encoder-Decoder架构，Encoder双向读取信息，再由Decoder输出结果。而gpt仅有decoder，输入和输出都在同一个token序列里，读取时通过掩码忽略未来的token，输出时同时读输入和输出的部分，推测下一个token的内容，所以被称为Decoder-only。
